# Reset — 2026-08-04

Owner decision. Everything from the current generation discarded and the
forward clock restarted. This file exists so the reset is a recorded
event rather than an unexplained gap in the record.

## Why

Two bugs surfaced while grading the epoch-2 seeds:

1. **Permutation blindness (introduced by the epoch-2 plumbing).**
   `permutation_p` shuffled closes, but `windows_for` routes full-candle
   seeds through a bar cache and ignores the closes argument. Every
   epoch-2 seed was regraded on the REAL data each iteration, so
   criterion 9 returned p=1.0 by construction — an automatic FAIL that
   looked like a genuine result. Fixed by `permute_bars()` before any
   verdict was recorded.
2. **Ledger unwritable (pre-existing, latent since 9c68af8).** `run()`
   wrote the results CSV before `ledger_record_1h`, which re-checks for a
   clean tree — so writing the artifact dirtied the tree and the ledger
   write always threw. No verdict had been recordable since that guard
   landed.

## What was discarded

- Exam ledger: 38 rows cleared to 0.
- Epoch-2 exam artifacts (8 recorded crypto verdicts, all FAIL).
- Epoch-2 seed rosters (`seeds_crypto_v2`, `seeds_stocks_v2`) and
  `dryrun_v2`.
- Forward record: squad states, league state, all equity/trade/decision/
  daily logs, diversity log.

Both epoch-1 rosters were set `ARMED = False`. Their forward record no
longer exists, so they must not silently resume against a fresh state
file as if nothing happened. Re-arming is an explicit owner act.

## What was NOT discarded, and why

**Everything above is archived**, not deleted, in
`archive/epoch2_discarded_20260804/` — ledger, results, state, logs,
seeds, proposal doc. Discarding a generation is a decision; destroying
the evidence of it is not required by that decision.

**K, the multiple-testing counter, was carried forward.** See
`backtest/results/k_offset.json`. The NAMES are cleared, so nothing from
the discarded generation competes with or constrains what comes next.
The TRIAL COUNT is preserved because those trials genuinely happened
against this same price data: 38 names were tested, 31 screened. Zeroing
K would not reset the luck hurdle to neutral — it would set it LOWER
than reality, making a false PASS easier to obtain than it was before
the reset. K is the one number in this system that may get harder to
satisfy but never easier.

Current: K = 69, luck hurdle Sharpe 1.197.

To zero it as well, set both fields in `k_offset.json` to 0. That is
available, but it should be a deliberate recorded act, not a side effect
of a cleanup.

## Engine state after the reset

The epoch-2 ENGINE changes were kept:

- full-candle interface (`step_bars`, bounded `tail`)
- per-bot conviction ordering (the fix for the 8-of-10 identical-books
  finding; `edge_proxy` remains the signal-free s4.3 cost gate)
- roster-configurable `MAX_POS`, cross-asset context, cross-sectional
  contract
- `bot/diversity.py` overlap gauge
- `data/pit_stocks.py` point-in-time stock membership
- both exam bug fixes

These were kept because reverting them would restore the known-defective
tie-breaker that caused the finding this whole generation was built to
address. They are inert with no armed roster. Say so and they come out.

## Open item carried forward

The discarded epoch-2 roster had a real design flaw worth not repeating:
declared holding horizons did not match observed behaviour. `h2_obv`
declared a 120h hold and traded roughly every 28 bars; it booked 2,422
trades and lost effectively everything to fees. Any future roster should
check declared horizon against realised turnover BEFORE the exam, not
after.
